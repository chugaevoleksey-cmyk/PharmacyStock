# Стандарт кодування та конструктивних практик PharmacyStock

Версія стандарту 1.0.0. Власник: Чугаєв Олексій Михайлович, група 471. Чинний для нових змін від 21.11.2026. Варіант 19, C# 12, .NET 8. Версія стандарту незалежна від версії застосунку 0.8.0.

## 1 Сфера дії та словник

Стандарт застосовується до PharmacyStock.Core, PharmacyStock.App та їхніх тестів. Згенеровані bin/obj, сторонні пакети, історичні навчальні приклади в docs і допоміжні інструменти вимірювання не є production-кодом. Legacy з попередніх робіт змінюється за правилом бойскаута; міграційний борг реєструється, а не приховується від аналізу.

ОБОВ’ЯЗКОВО означає відмову збірки для машинного правила або блокування PR для семантичного правила рев’ю. РЕКОМЕНДОВАНО — відступ потребує змістовної причини в PR. ДОПУСКАЄТЬСЯ — обидва варіанти прийнятні. ЗАБОРОНЕНО — рівень для безумовно неприйнятної конструкції; у цій версії такі конструкції описано обов’язковими негативними приписами, щоб не дублювати правила. 42 із 70 правил (60%) обов’язкові, решта рекомендовані або допустимі. Наявність warning у конфігурації при TreatWarningsAsErrors=true фактично зупиняє складання; suggestion лишається підказкою.

Ідентифікатори: N — назви; F — формат; C — коментарі; D — дані; S — керування; A — автоматизація; X — аптечна специфіка. Картка правила містить припис, рівень, причину, пару прикладів і перевірку. Номер не перевикористовують після скасування. На рев’ю посилаються на номер та конкретний рядок зміни.

Усі «погано» нижче — навмисні контрприклади для PharmacyStock, а не твердження про дефекти, що колись були в репозиторії. Проєктовані Dose, DoseUnit та партії з терміном придатності ще не реалізовано у поточній Medicine; вони визначають контракт наступного розширення. Поточні Stock і PrescriptionLine.Quantity означають цілі одиниці, не дробову медичну дозу.

Реальний RateFor у PharmacyStock.Core/Pricing/PrescriptionDiscountPolicy.cs: базове значення 1, умовний вираз isRegular ? ... : ... дає +1, if (amount >= BigPrescriptionFrom) дає +1. Отже CC = 3. Його результати не називаємо повним автоматичним порогом збірки.

## Фінансові та часові контракти

Застосунок веде суми UAH. Промо-знижка рецепта та ціна окремої позиції — різні політики: їх не можна мовчки об’єднувати. Чинний ToEven зафіксований тестами; приклад AwayFromZero у методичці не є дозволом змінити результати. Для фінального чека точку округлення визначає відповідна політика; не додавати додаткове округлення на кожному проміжному множенні. Якщо з’явиться інша валюта, сума й CurrencyCode мають передаватися разом, без неявного перерахунку.

У проєктованій партії інтервал придатності [ReceivedDate, ExpiryDateExclusive). Коли на упаковці вказано останній придатний день, імпорт один раз перетворює його на наступну дату як виключну межу. Для DateOnly.MaxValue імпорт відмовляє замість переповнення AddDays. Це проєктний контракт обліку, який потрібно підтвердити вимогами замовника, а не медична рекомендація. Для дози 0.5 mg зберігається 0.5m та Milligram; округлення грошей до копійок до доз не застосовується.

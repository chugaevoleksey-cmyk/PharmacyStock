# Стандарт кодування проєкту PharmacyStock

## 1. Загальні положення

Цей документ описує основні правила написання та оформлення коду навчального проєкту PharmacyStock (варіант №19). Проєкт призначений для обліку лікарських засобів і рецептів в аптеці та розробляється мовою C# на платформі .NET 8.

Основна мета стандарту - забезпечити зрозумілість коду, однакове оформлення всіх файлів і зручність подальшого внесення змін.

## 2. Іменування

| Сутність | Правило | Правильний приклад | Неправильний приклад |
|---|---|---|---|
| Клас | PascalCase, іменник | PrescriptionLine | prescriptionline |
| Інтерфейс | I + PascalCase | IMedicineRepository | MedicineRepository |
| Метод | PascalCase, дієслово | AddLine | addline |
| Властивість | PascalCase | UnitPrice | unitprice |
| Приватне поле | _camelCase | _lines | m_Lines |
| Локальна змінна | camelCase | totalAmount | ta |
| Константа | PascalCase | MaxLineCount | MAX_LINE_COUNT |
| Перелічення | PascalCase, однина | PrescriptionStatus | PrescriptionStatuses |

Назви класів, методів і змінних повинні відображати їхнє призначення. Не рекомендується використовувати незрозумілі скорочення.

## 3. Форматування

У проєкті встановлено такі правила:

1. Для відступів використовуються 4 пробіли.
2. Табуляція для відступів не використовується.
3. Довжина рядка коду не повинна перевищувати 100 символів.
4. Фігурні дужки розміщуються на новому рядку за стилем Allman.
5. Фігурні дужки обов'язкові навіть для одного оператора в умовах і циклах.
6. Між методами та іншими членами класу залишається один порожній рядок.
7. Директиви using розміщуються на початку файлу.
8. Невикористані директиви using видаляються.
9. Простори імен оформлюються у файловому стилі (namespace PharmacyStock.Core.Domain;).
10. Кожен файл має завершуватися символом нового рядка.

## 4. Коментарі та документація

Коментарі повинні пояснювати причину певного рішення, а не просто повторювати написаний код.

Поганий приклад:

```csharp
// Додаємо одиницю
count = count + 1;
```

Кращий приклад:

```csharp
// Для контролю залишків не дозволяємо від'ємну кількість
if (quantity < 0)
{
    throw new ArgumentOutOfRangeException(nameof(quantity));
}
```

Для основних публічних класів і методів використовується XML-документація.

Наприклад:

```csharp
/// <summary>
/// Обчислює загальну вартість ліків у рецепті.
/// </summary>
/// <returns>
/// Загальна вартість позицій рецепта.
/// </returns>
```

## 5. Структура проєкту

Рішення PharmacyStock складається з двох проєктів:

- **PharmacyStock.Core** - бібліотека класів із предметною логікою.
- **PharmacyStock.App** - консольний застосунок, який використовує бібліотеку.

У папці Domain розміщуються основні сутності: Patient, Medicine, Prescription, PrescriptionLine та PrescriptionStatus.

Логіка обчислень повинна залишатися в бібліотеці Core. Консольне введення та виведення виконується в App.

## 6. Правила комітів

Для контролю версій використовується Git.

Кожен коміт повинен відображати одну завершену зміну. Повідомлення оформлюються за принципом Conventional Commits:

- feat: додавання нових можливостей;
- fix: виправлення помилок;
- docs: оновлення документації;
- chore: налаштування інструментів;
- style: зміни форматування.

Приклади:

`feat: додано доменний скелет варіанта 19`

`chore: налаштовано аналізатори StyleCop`

`docs: додано стандарт кодування і README`

До репозиторію не додаються тимчасові файли та результати складання з папок bin і obj.

## 7. Правила, закріплені машинно

| Пункт стандарту | Механізм перевірки | Правило |
|---|---|---|
| Відступ у 4 пробіли | .editorconfig | indent_size = 4 |
| Використання пробілів | .editorconfig | indent_style = space |
| Кодування UTF-8 | .editorconfig | charset = utf-8 |
| Новий рядок у кінці файлу | .editorconfig, StyleCop | insert_final_newline, SA1518 |
| Приватні поля з підкресленням | Аналізатор іменування | IDE1006 |
| Обов'язкові фігурні дужки | .editorconfig | csharp_prefer_braces |
| Стиль Allman | .editorconfig | csharp_new_line_before_open_brace |
| Правильні пробіли | StyleCop | SA1028 |
| Порядок членів класу | StyleCop | SA1201 |
| Фігурні дужки для тіла конструкції | StyleCop | SA1503 |
| Порожні рядки між членами класу | StyleCop | SA1516 |
| Загальне форматування | dotnet format | IDE0055 |

Для автоматичної перевірки використовуються Roslyn і StyleCop.Analyzers.

Команди перевірки:

```powershell
dotnet format --verify-no-changes
dotnet clean
dotnet build
```

Перед збереженням завершених змін у Git проєкт має успішно збиратися без помилок і попереджень.

# Метрики до рефакторингу

Метод вимірювання: Roslyn SyntaxTree без пакета Metrics. LOC — непорожні рядки, крім рядків-коментарів; включає сигнатуру й фігурні дужки. CC = 1 + if, for/foreach/while/do, catch, case, &&, ||, ??, ?:; else не враховано. Вкладеність — максимальна кількість вкладених керувальних конструкцій, else if не додає рівня до попереднього if. Вимірюється лише src/Legacy, без bin/obj. Лістинги взято всі 6.1–6.7: попереднє речення методички згадує лише 6.1–6.5, але Preview/DescribeClient/DumpLog необхідні для завдань.

Реальні LOC відрізняються від орієнтовної таблиці методички через її розбиття на лістинги та визначення рядка. Початковий Handle має CC = 17: 4 перевірки валідації + || + && + 2 for + 3 перевірки знижки + 3 обмеження + доставка + sendMail = 16 точок; 1 + 16 = 17.

## Порівняння
Метрики рахуються тим самим аналізатором і тим самим правилом до та після. Сам початковий файл має 149 значущих рядків, а процесор без двох моделей — 130: обидва числа не треба змішувати. Вбудований аналізатор використовує Roslyn зі встановленого SDK 10; пакет із NuGet не потрібен. Для відтворення: `dotnet run --project tools/LegacyMetrics -- src/Legacy`. Усі проєкти застосунку та тестів лишаються net8.0; Metrics — окремий службовий інструмент net10.0, не включений до рішення. Список усіх точок — metrics-before.json / metrics-after.json.

| Показник | До | Після |
|---|---:|---:|
| Handle LOC | 80 | 16 |
| Handle CC | 17 | 3 |
| Handle вкладеність | 4 | 1 |
| Handle параметри | 11 | 1 |
| LOC модуля | 149 | 156 |
| Копії алгоритму розрахунку | 2 | 1 |
| Магічні бізнес-значення поза PricingRules | 7 | 0 |
| Тимчасові поля | 2 | 0 |

Максимальна CC окремого методу після: 7; не слід підміняти її CC Handle. У Validate збережено всі перевірки, тому складність не зникла безслідно. Зростання загального LOC пояснюється деклараціями політик, enum, констант та об’єкта запиту.

До і після ті самі 30 характеризаційних тестів і 61 попередній тест зелені. Перевірено 11 комітів від стану перед рефакторингом до останнього кроку: кожен дає 30 + 61 успішних тестів. SHA256 LegacyCharacterizationTests.cs однаковий на всіх комітах; змінювався лише LegacyCalls.cs для викликів нового API. Це підтверджує збереження поведінки на покритих сценаріях, а не математичну еквівалентність на всіх можливих входах.

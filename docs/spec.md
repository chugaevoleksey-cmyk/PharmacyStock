# Специфікація PharmacyStock 1.0

## Межі
Входить: умовний каталог, партії, рецепт, відпуск FEFO, надходження,
пошук за кодом і назвою, близькі терміни, локальний JSON, журнал.
Не входить: медичні рекомендації, реальні пацієнти, контрольовані речовини,
електронний рецепт держави, каса, база даних, одночасна робота операторів.
Дозування тут — навчальний ліміт одиниць на один відпуск, а не медична доза.
Усі межі умовні й не придатні для практики аптеки.

## Правила R01–R09
R01: код і назва непорожні, ціна > 0; кількість 1..1000.
R02: надходження з терміном сьогодні дозволено; раніше сьогодні відхиляється.
R03: відпуск враховує лише партії з терміном >= сьогодні, кількість > 0.
R04: Rx-препарат потребує Approved рецепта з потрібною позицією;
рецепт діє 30 днів включно; майбутня дата заборонена.
R05: кількість <= ліміту препарату та кількості позиції; частковий відпуск
закриває рецепт цілком. Багатопозиційний відпуск поза межами цієї версії.
R06: при відмові запас і стан не змінюються. Після успіху рецепт Dispensed.
R07: ціна каталогу × кількість; decimal, округлення 2 знаки AwayFromZero;
знижок немає. Нульова та від'ємна кількість — помилка вводу.
R08: близькі терміни: [сьогодні; сьогодні + N], N=0..90, тільки залишок > 0;
сортування за датою, кодом, номером партії. Прострочені не включаються.
R09: у файлі тільки умовні ідентифікатори; завантаження повністю перевіряє
дані до заміни робочого стану. Пошкоджений файл не перезаписується автоматично.

|---|---|---|---|---|

## UC-01 Відпустити ліки за рецептом
Дійова особа: фармацевт. Мета: Отримати оплату і списати придатні одиниці.
Передумова: Каталог і партії завантажені; для Rx є підтверджений рецепт.

1. Оператор задає код, кількість і номер рецепта.
2. Система перевіряє ввід і знаходить препарат.
3. Система перевіряє рецепт, ліміт і сумарний придатний запас.
4. Система розподіляє кількість за FEFO.
5. Система списує запас і закриває рецепт.
6. Система показує суму та записує завершення.

Альтернативи:
- 2а: код невідомий — повідомлення, змін немає.
- 3а: рецепт або дозування недопустимі — Warning, змін немає.
- 3б: недостатньо придатного запасу — відмова без часткового списання.

Постумова: Запас зменшено, рецепт Dispensed, сума округлена.
Правила й тести: Dispense_*; DispensingPolicy_*; R03–R07.

## UC-02 Оприбуткувати надходження
Дійова особа: комірник. Мета: Збільшити запас новою партією.
Передумова: Препарат є в каталозі.

1. Оператор задає номер партії, код, кількість і дату.
2. Система перевіряє всі поля.
3. Система відхиляє дубль номера чи прострочення.
4. Система додає партію та показує залишок.

Альтернативи:
- 2а: кількість нечислова або <=0 — повторний ввід.
- 3а: номер зайнятий — повідомлення, запас незмінний.
- 3б: дата минула — відмова.

Постумова: Є нова партія з додатним залишком.
Правила й тести: Receive_*; R01–R02.

## UC-03 Створити і провести рецепт
Дійова особа: фармацевт. Мета: Підготувати документ для одного відпуску.
Передумова: Відомий код препарату.

1. Оператор задає умовний номер пацієнта, код і кількість.
2. Система перевіряє дані й створює New рецепт із позицією.
3. Оператор підтверджує або скасовує документ.
4. Система перевіряє перехід і показує новий стан.

Альтернативи:
- 2а: невідомий код — документ не створено.
- 3а: закритий документ — власний виняток домену, стан незмінний.
- 3б: порожній рецепт не підтверджується.

Постумова: Новий документ має стан Approved або Cancelled.
Правила й тести: Create_*; Transition_*; таблиця станів.

## UC-04 Знайти препарат
Дійова особа: оператор. Мета: Переглянути код, назву й ціну.
Передумова: Каталог завантажено.

1. Оператор задає критерій code або name і рядок.
2. Система перевіряє критерій.
3. Система виконує пошук без урахування регістру.
4. Система показує записи в порядку кодів.

Альтернативи:
- 2а: критерій невідомий — повідомлення.
- 3а: збігів немає — «Нічого не знайдено».

Постумова: Стан даних незмінний.
Правила й тести: Search_*.

## UC-05 Показати ліки з близьким терміном
Дійова особа: комірник. Мета: Побачити залишки, які потрібно використати першими.
Передумова: Є каталог і партії.

1. Оператор задає горизонт у днях.
2. Система перевіряє межі 0..90.
3. Система відбирає непрострочені ненульові залишки.
4. Система впорядковує й показує код, партію, дату, кількість.

Альтернативи:
- 2а: -1 або >90 — повідомлення, звіт не будується.
- 3а: немає партій — «Нічого не знайдено».

Постумова: Побудовано звіт, запас незмінний.
Правила й тести: Expiring_*; R08.

## UC-06 Зберегти або завантажити дані
Дійова особа: оператор. Мета: Продовжити роботу після перезапуску.
Передумова: Задано шлях локального файла.

1. Оператор обирає зберегти або завантажити.
2. Система створює повний знімок або читає JSON.
3. При читанні система перевіряє всі зв’язки та значення.
4. Після успіху система замінює стан або атомарно файл.

Альтернативи:
- 2а: доступ заборонено — Error і зрозуміле повідомлення.
- 3а: JSON або дані некоректні — старий стан і файл зберігаються.

Постумова: Файл і пам’ять відповідають успішній операції.
Правила й тести: Store_*; R09.

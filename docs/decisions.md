# Інженерні рішення
Усі записи прийняті 21.11.2026 під час СР3. Попередні рішення лабораторних
зберігаються в історії та archive; дати не відновлювалися заднім числом.

## ADR-01 Залишити Core та винести Infrastructure
Контекст: у лабораторних файл і консоль сусідили з логікою, для СР3 потрібен контроль меж.
Альтернативи: одна бібліотека з тестом; окремі Domain/Application/Infrastructure;
Core (домен і прикладний шар) плюс Infrastructure та App.
Рішення: третій варіант, Core без зовнішніх ProjectReference.
Наслідки: компілятор блокує зворотну залежність; менше проєктів, але між
доменом і прикладним шаром усередині Core межа лишається організаційною.

## ADR-02 JSON замість CSV
Контекст: документ містить позиції та стан. CSV потребує кількох файлів і зв'язків.
Рішення: окремий DTO-знімок у JSON, валідація до заміни стану, запис у тимчасовий
файл і перейменування. Тільки пам'ять не дозволяла б продовжувати роботу.
Наслідки: структура читається людиною, атомарна заміна; весь файл у пам'яті,
немає паралельного запису чи гарантії fsync при аварійному вимкненні.

## ADR-03 Розділити помилки вводу й домену
Контекст: нечислова кількість — очікувана помилка, закритий рецепт — порушення правила.
Рішення: Validation для структурних помилок; DomainRuleException для правила;
ArgumentException для обходу контракту програмістом. Порожні catch не використовуються.
Наслідки: користувач може повторити команду; потрібно підтримувати два явні шляхи відмови.

## ADR-04 Перевірити план FEFO до списання
Контекст: послідовне списання могло змінити першу партію до виявлення нестачі.
Рішення: повністю збудувати план, перевірити рецепт і запас, лише тоді застосувати його.
Наслідки: відмова не змінює залишки; додаткова короткоживуча колекція плану;
паралельна робота все одно потребувала б блокування або транзакції.

## ADR-05 Підміняти годинник та сховище
Контекст: Today і JSON робили б межі 30/31 день залежними від машини.
Рішення: IClock, IStockRepository, ручні FakeClock та FakeRepository, без mocking-пакета.
Наслідки: детерміновані тести; більше невеликих типів і окремі інтеграційні тести JSON.

## ADR-06 Відмовитися від медичних доз і багатопозиційного відпуску
Контекст: варіант вимагає дозування; справжнє дозування залежить від клінічних даних,
яких немає в завданні. Розглянуто медичний калькулятор і навчальний ліміт одиниць.
Рішення: явно умовний ліміт 10 одиниць, один рецепт — одна позиція — один відпуск.
Наслідки: правило відтворюється тестами; програма непридатна для реальної аптеки,
частковий відпуск закриває документ, розширення оформлено TD-01.

## ADR-07 Зберегти семестрову історію і чесно описати строки
Контекст: типовою віддаленою гілкою була lab6-refactoring; main містив ЛР8.
Рішення: merge main, незмінний архів вихідних файлів, окремі малі коміти СР3
після локального build/test. Не підміняти дати заради вимоги шести днів.
Наслідки: обидві лінії історії доступні; формальний критерій шести днів СР3
залишається невиконаним, навіть коли у всій семестровій історії дат більше.

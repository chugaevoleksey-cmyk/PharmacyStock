# Чекліст змістового огляду PharmacyStock

- [ ] 2. Чи запит не приховує збереження або сповіщення? N-16.
- [ ] 3. Чи всі поняття узгоджені з аптечним глосарієм? N-15.
- [ ] 4. Чи зміна вирішує одну описану задачу, без випадкової переробки сусіднього коду?

## Дані й аптечні одиниці
- [ ] 5. Чи правильно обрано місце та правило округлення саме цієї фінансової величини? D-14.
- [ ] 6. Чи не переплутано дозу, кількість упаковок, масу та об’єм? X-02–04.
- [ ] 7. Чи включення останнього дня придатності узгоджено з імпортом? X-01.
- [ ] 8. Чи конвертація одиниць має явну концентрацію та обґрунтовану точність? X-04.
- [ ] 9. Чи API колекції не відкриває обхід інваріантів через mutable backing object? D-10.
- [ ] 10. Чи іменована константа справді стала, а не тариф, що має бути конфігурацією? D-06.

## Документація й борг
- [ ] 17. Чи зміст XML відповідає побічним ефектам і свідомим виняткам, а не лише формально присутній? C-07.
- [ ] 18. Чи новий виняток зі стандарту має причину, власника й дату перегляду? C-06.

Культура: зауваження адресують коду, не автору. Кожне зауваження містить конкретну дію й ID правила: «У PrescriptionService передайте у Pay готовий request, щоб прибрати шість параметрів», а не «погано написано». Відступи, using, наявність XML та зелений build не дублюються у цьому ручному списку — вони мають власну автоматичну перевірку.
